## Closed correction decisions

### Heating proof is episode evidence, never relay truth

Keep the existing 2°C/300 s proof thresholds. `confirmed` means temperature rose during the currently observed continuous Dry episode. It does not mean the element is presently energized. At-target remains distinct; timer-running alone remains insufficient.

Reset proof/baseline/watch on a fresh complete snapshot with Dry OFF, work_on OFF, or mode outside Dry; on disconnect/availability loss/reconnect; and when an accepted stop intent or a new start/recovery attempt invalidates the old observation. Detect a telemetry gap older than 10 s before replacing the old snapshot so a subsequent fresh ON cannot revive old proof. A pending watchdog must never confirm from cooling/residual warmth after OFF or from an obsolete baseline. An unconfirmed stop invalidates heating proof but DOES NOT confirm physical OFF, clear pending Stop, or resolve `_latch_seq`.

Expose one transport read method `heating_evidence_status() -> str` for Panda's two reports. It returns `unknown` when no fresh valid snapshot exists; `none` for fresh non-Dry/work-off/drying-off state; otherwise the current episode's `pending|confirmed|at_target|unconfirmed`, or `none` when no proof was begun. This is a report, never a command or recovery trigger. Make any internal invalidation idempotent. Do not clear `start_status` or its latch merely to match a terminal session: start status is explicitly the last attempt, a different fact.

Panda uses that method for `dry_heating_confirmed` and sets the legacy binary `heating` ON only when it returns confirmed; otherwise OFF means **no current confirmed rise evidence**, not physical heater OFF. On unavailable transport publish proof unknown and availability OFF as already supported. Never use stale `last_ws_settings` to determine native Heat. If a test double lacks the method, fail closed to unknown rather than trust its raw confirmed flag; update the shared fake faithfully. Preserve the native device fields as device readings, not a synthetic host countdown.

### Direct native temperature settings

Reject nonfinite and numeric values outside inclusive 40–60 **before** `int()` at each command boundary. In-range fraction-to-int behavior remains as before; changing supported resolution is unnecessary. Return False atomically from transport translation (including mixed envelopes), with zero publishes. Mod rejects before updating `filament_temp`, retained `dry_temp` or scheduling device work; log the refused input without claiming device acceptance. Keep 40, 48 and 60 valid; no timer/mode/ON writes from these setters. Native HA discovery uses 40/60; legacy settings/discovery stay unchanged. Web remains a generic publisher; backend validation is authoritative. Do not reject out-of-range incoming telemetry, because that could hide state needed for Stop.

### Generic ON cannot be a second Dry-start owner

At execution inside the existing command lock, native work_on ON must have fresh `drying_snapshot()` and must be outside Dry, with neither running nor pending-stop supervised intent and no intervening cancel/lock. Otherwise log refusal and send nothing; do not optimistically publish a successful `work_on=1` for that refused request. It neither cancels an armed session nor creates one. Capture/recheck the existing dry generation for a queued ON overtaken by OFF; do not hold a threading lock across an await or wait for telemetry while holding cancellation persistence.

For accepted native non-Dry ON, send only `{"settings":{"work_on":1}}`. Preserve existing legacy ON envelope. OFF still persists cancellation before sending its existing stop envelope, and pending Stop only clears on post-write fresh OFF. This is closing a demonstrated alternate Dry-start path, not assuming firmware timer-reset behavior or redesigning Power/manual controls.

### Clock diagnostic

`status()` reads finite wall and monotonic clocks defensively and compares monotonic time with the existing high-water mark without advancing it. Pass those observations to `_inhibit_reason`. Preserve its priorities/reason vocabulary: no session, persistence failure, invalid state, real monotonic regression, unusable clocks, elapsed deadline. A valid running session before deadline reports inhibit None. Querying status must not change `_last_mono`, deadlines, state bytes, observation counters or active tasks. Keep `_clock_state()`'s operational mutation in tick, not status. Do not add a new cancellation/status model.
